# order-java 项目模块架构说明

## 项目概览

这是一个基于 Maven 的多模块 Spring Boot 项目，专注于交易订单系统(jjewelry珠宝电商)。项目版本为 0.4.0-SNAPSHOT，使用了典型的微服务分层架构。

**项目坐标**:
- groupId: `cn.mathmagic.jjewelry`
- artifactId: `order-java`
- 父项目: `framework-parent:1.0.9`

---

## 核心模块分析

### 1. trade-order-client (客户端/API接口层)

**职责**: 对外提供 Feign 接口定义，供其他服务调用

**技术栈**:
- Spring Cloud OpenFeign 2.2.9
- Swagger 2.9.2
- Jackson
- Lombok

**主要内容**:
- **客户端接口**: AfterSaleOrderClient, IkjOrderClient, PaymentClient, SpuClient, ErpClient, FrontCategoryClient等
- **DTO对象**: 数据传输对象，包含请求/响应模型
- **枚举定义**: ErpSyncStatus, ProductStageEnum, ProductionStatusEnum, TradeProductStatusEnum等
- **命令对象**: AttributeCreateCmd, CategoryCreateCmd, FreightTemplate相关DTO等

**特点**: 
- 无业务逻辑，纯接口定义
- 可被其他微服务依赖
- 会发布到Maven仓库供其他项目使用

---

### 2. trade-order-service (服务层/业务逻辑层)

**职责**: 核心业务逻辑实现

**技术栈**:
- MyBatis 2.1.3
- MySQL 8.0.20 + Druid连接池
- Redis + Redisson 3.11.4
- Elasticsearch
- RocketMQ 2.3.1
- Nacos配置中心 0.2.10

**主要业务模块**:

#### 订单管理 (order)
- 订单创建、支付、发货、完成
- 订单状态流转
- 生产订单管理 (ProductionOrder)
- 订单地址管理

#### 商品管理 (product/attribute/category)
- SPU/SKU管理
- 商品分类 (Category)
- 商品属性 (Attribute)
- 定制化商品配置
- 商品搜索索引

#### 支付模块 (payment)
- 微信支付 (wechatpay-java 0.2.16)
- 支付宝支付 (alipay-sdk-java 4.40.272)
- 支付回调处理
- 退款管理

#### 营销模块 (marketing/promotion/coupon)
- 促销活动管理
- 优惠券系统 (Coupon)
- 折扣记录 (DiscountRecord)
- 想要它 (WantIt) 营销功能

#### 物流模块 (freighttemplate/shipping)
- 运费模板管理
- 快递追踪
- 发货管理

#### 售后服务 (aftersale)
- 售后订单管理
- 退款处理
- 售后审核

#### 集成服务
- **ERP集成**: 嘉云ERP对接 (Jackyun)
- **第三方平台**: 小红书订单同步
- **告警通知**: 飞书告警服务
- **短信通知**: SMS服务集成
- **文件存储**: 火山引擎TOS对象存储 2.6.6

**依赖的外部服务**:
- `uc-aigc-client` - AI生成服务
- `uc-auth-sdk` - 用户认证服务
- `fulfill-client-compat` - 履约服务
- `ecommerce-supplier-client` - 供应商服务
- `push-service-client` - 推送服务
- `jjewelry-generator-client` - 生成器服务
- `jjewelry-aigc-client` - AI生成客户端
- `short-link-client` - 短链接服务

**特点**:
- 不发布到Maven仓库 (maven.deploy.skip=true)
- 包含MyBatis XML映射文件
- 使用Aviator 5.4.1表达式引擎
- Caffeine 2.9.3本地缓存防止内存溢出

## 模块依赖关系

```
trade-order-api    ──┐
                     ├──> trade-order-service ──> trade-order-client
trade-order-job    ──┘
```

**依赖说明**:
- **trade-order-client**: 最底层，定义接口和DTO，被所有模块依赖，会发布到Maven仓库
- **trade-order-service**: 中间层，实现业务逻辑，依赖client，被api和job依赖
- **trade-order-api**: 应用层，提供REST API，依赖service
- **trade-order-job**: 应用层，执行定时任务和消息消费，依赖service

## 开发建议

### 1. 添加新接口
在 `trade-order-client` 模块中定义Feign接口和DTO，然后在 `trade-order-service` 中实现，最后在 `trade-order-api` 中创建Controller暴露HTTP接口。

### 2. 添加新定时任务
在 `trade-order-job` 模块中创建Job类，继承 `BaseJob`，使用 `@XxlJob` 注解标注。

### 3. 添加新消息消费
在 `trade-order-job` 模块中创建Consumer类，配置Kafka或RocketMQ监听器。

### 4. 数据库变更
- 实体类放在 `trade-order-service` 的entity包
- Mapper接口放在repository/mapper包
- MyBatis XML放在 `src/main/java` 对应包路径下

### 5. 缓存策略
- Redis用于分布式缓存
- Caffeine用于本地缓存(如表达式缓存)
- 注意缓存失效策略
