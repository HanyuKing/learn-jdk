# magician：统一优惠券标签展示

## 排序规则

- **可用券**：直接复用 `CouponQuoteOrder` 现有顺序，不新增排序策略、不修改该类：
    1. 最终应付金额升序；
    2. 实际优惠金额降序；
    3. `validEndTime` 升序；
    4. `couponId` 数值升序。
- **未达门槛券**：新增展示排序策略：
    1. 理论优惠金额降序；
    2. `validEndTime` 升序；
    3. `couponId` 数值升序。
- 理论优惠仅用于展示排序：满减、立减取 `discountValue`；折扣券按当前适用商品金额计算，忽略门槛校验，保留促销叠加规则、折扣上限及可抵扣金额限制。无法计算时记为 0。

## 展示行为

- 商详每个 SKU 的 `promotionLabelList` 返回全部可用券，再追加全部未达门槛券；例如 2 张可用、3 张未达门槛，共返回 5 张券标签。
- 商详券标签保留“优惠券名称 + 优惠规则”；范围不匹配、过期、已使用、促销冲突等券不进入标签。
- 购物车未勾选行复用现有真实购买数量下的独立 AUTO 报价：取第一张可用券；没有可用券时，取新策略排序后的第一张未达门槛券。
- 购物车未勾选行最多一张券标签，文案为“优惠券名称 + 使用门槛”，例如 `新人券 满50元可用`；保留现有券 ID、券名、门槛和跳转字段。
- 已勾选行保持现有整单报价及标签选择逻辑，不增加独立报价。促销标签仍排在券标签之前。

## 实现与兼容

- 在统一标签服务中复用已排序的可用券，只为未达门槛券抽取新排序策略；按商详、购物车场景分别渲染文案和控制标签数量。
- 理论优惠在现有券评估过程中计算并保存在内部结果中，不写入实际优惠字段，不增加对外 DTO 字段。
- 不改变 AUTO/SPECIFIED/NONE 选择、金额、运费、锁券行为；`compute/checkout` 的可用券顺序继续由现有 `CouponQuoteOrder` 决定。
- 本次新排序用于未达门槛标签展示，不重排其他不可用券，也不修改优惠券列表、历史券列表。
- 复用已加载的候选和报价数据，不新增逐行数据库、Redis 或 RPC 查询。
